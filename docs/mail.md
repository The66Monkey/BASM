# Self-hosted email

BASM Core uses **Stalwart as its complete email server**: inbound and outbound
SMTP, mailbox storage, IMAP, authenticated SMTP submission, and administration.
Thunderbird and ERPNext can use standard email protocols. No Postal service,
external email provider, or additional MariaDB is required. Stalwart stores
mailbox data in its persistent data directory using its embedded store; BASM's
coordinated backup includes that data.

## Initial setup

The first-run setup listener is bound to loopback only. From an administrator's
computer, open an SSH tunnel to the BASM host, using the setup port in the
private IT handover:

```sh
ssh -L 18082:127.0.0.1:18082 <server-user>@<server-address>
```

Open `http://127.0.0.1:18082` locally. The temporary initial login is printed
in the Stalwart container log; read it on the server and keep it private:

```sh
sudo docker logs basm-stalwart-mail
```

In the setup wizard:

1. Set the server hostname to `mx.<domain>` and add `<domain>` as a mail domain.
2. Keep the embedded data store and internal account directory.
3. Use console logging for Docker.
4. Configure TLS for `mx.<domain>`. Production TCP 443 is passed through
   Traefik to Stalwart; the hostname must resolve publicly for certificate
   provisioning. Add a Stalwart HTTP listener named `https-proxy` on
   `0.0.0.0:8443`, with implicit TLS and PROXY protocol trusted only from
   `172.31.255.2`. BASM's isolated `basm-mail-proxy` network sends the original
   client address to this listener.
5. Record the permanent administrator password shown at the end; it is shown
   only once.

BASM's isolated `basm-mail-proxy` network uses `172.31.255.0/29`, with Traefik
at `172.31.255.2` and Stalwart at `172.31.255.3`. Check that subnet against
existing Docker and VPN routes before deployment; if it overlaps, change the
subnet and both assigned addresses and Stalwart's trusted proxy address
together.

After setup, restart the Stalwart container and sign in at
`https://mx.<domain>/admin`. Create a mailbox for the owner and keep mailbox
credentials in the owner's password manager. Use a separate mailbox/account
for ERPNext's authenticated SMTP sending rather than the Stalwart administrator.
The admin UI is reachable over public HTTPS by default and requires Stalwart
authentication. Use the canonical `mx.<domain>` hostname: Stalwart publishes
the admin app's OAuth metadata there. The optional `mail.<domain>` alias
redirects to `mx.<domain>`; using a non-canonical host can fail authentication
with “Client metadata documents are disabled.” The SSH tunnel above is only
for first-run setup. After setup, the admin app's OAuth client ID is bound to
the canonical HTTPS origin; signing in through `localhost` or an IP address
can fail with “Unknown client id.” Wait for a trusted certificate and then
sign in at `https://mx.<domain>/admin`; do not bypass certificate warnings.
`/account` is the user account manager, not a webmail client; read messages
through an IMAP client such as Thunderbird.

In **Management > Domains**, use **View Zone File** as the source for Stalwart's
current DNS records. Publish required mail records and service-discovery or
TLSA records only for protocols and ports reachable from their intended
clients. Do not publish records for disabled services or bypass a public
certificate warning.

## DNS and delivery requirements

Use the private DNS handover generated by BASM for the A, MX, SPF, DMARC and
mail-host records. After adding the domain in Stalwart, publish both current
DKIM keys and the generated policy/reporting TXT records. Merge SPF and DMARC
with existing records; do not create duplicate SPF records or overwrite
unrelated TXT records. Add service-discovery and TLSA records only for active
services reachable from their intended clients.
Publish service records only for protocols enabled and reachable in the
deployment. The standard BASM Compose setup publishes SMTP 25, submission 465
and IMAPS 993, but not POP3S 995; omit the generated `_pop3s._tcp` and
`_995._tcp` records unless POP3S is separately enabled and reachable.

The default ACME certificate request also covers `autoconfig`, `autodiscover`,
`mta-sts` and `ua-auto-config` under the mail domain. Each name must reach BASM
directly or through its configured edge, and every upstream proxy must pass the
`mx` and alias SNI names through to Stalwart for TLS-ALPN validation and
preserve client addresses with PROXY protocol. BASM Traefik routes to
`stalwart-mail-proxy:8443` over its
isolated network using PROXY protocol v2. BASM Traefik must trust only the
exact upstream-edge LAN address in its PROXY protocol entrypoint; the edge
sends PROXY protocol v2 to BASM. A TLS-terminating edge needs explicit TCP
passthrough routes for
the ACME `acme-tls/1` challenge on all mail hostnames. Use DNS-01 for
edge-managed certificates so the edge does not intercept the same challenge.
Do not bypass certificate warnings in a mail client.
Self-hosting avoids a third-party email provider, but still depends on a working
domain/DNS service, a reachable public IPv4 address, and a network path that
permits inbound and outbound TCP 25. BASM supports dynamic IPv4: the installer
sets up deSEC updates for its managed A records by default, checking every
15 minutes. A changed address can take up to 15 minutes to appear in DNS.
Reverse DNS (PTR) is controlled by the address-range owner and is not managed
by deSEC or BASM. If you do not have reverse-DNS control, mail can still be
received and sent, but some recipient servers may reject or junk outbound mail
because of the address's PTR or reputation.

When BASM sits behind an upstream VM or gateway, forward public TCP 25
end-to-end to Stalwart; do not send SMTP through an HTTP reverse proxy. Ports
465 and 993 must be reachable
from the networks where authorized mail clients run. For VPN-only access, keep
them private and ensure VPN routing and DNS resolve `mx.<domain>` to BASM while
preserving that hostname for TLS. Do not expose them publicly unless remote
mail-client access is intended. If LAN clients use private DNS and public
ports 465/993 are not forwarded, add a private DNS rewrite for
`mx.<domain>` to BASM's LAN address; leave the public `mx` record pointed at
the public mail address. Residential, dynamic, or previously used IP addresses may have poor sender
reputation. Local-mode installs are for testing and cannot receive internet
mail.

## Thunderbird

Add the created mailbox as an IMAP account. If Thunderbird does not discover the
settings automatically, enter:

| Setting | Value |
| --- | --- |
| Incoming protocol | IMAP |
| Incoming server | `mx.<domain>` |
| Incoming port/security | 993 / SSL/TLS |
| Outgoing server | `mx.<domain>` |
| Outgoing port/security | 465 / SSL/TLS |
| Username | Full email address |
| Password | The mailbox password |

With a custom port profile, map the standard client ports to the selected
server-side ports on the client network. Clients still use ports 465 and 993;
these can remain private when clients connect over the company LAN or VPN.

## Application email and acceptance

Configure ERPNext's outgoing email account with the dedicated Stalwart sender
account, server `mx.<domain>`, port 465, SSL/TLS, and authenticated username and
password. This supports invoice and other ERPNext notifications without an
external provider. Verify the From address is authorized by the configured
mail domain.

Send a message from Thunderbird to an unrelated mailbox and reply to it. Verify
both directions, SPF/DKIM/DMARC results, the received Stalwart mailbox, and
delivery from ERPNext. Also confirm unauthenticated external relay is rejected.
Check both Inbox and Junk during inbound tests; spam scoring may file a probe
there. SMTP acceptance, open ports and a running container alone do not prove
delivery or sender reputation.

## BASM-Plus

Postal is not deployed by BASM Core. A separate
[BASM-Plus project](https://git.scandinavianhacking.dedyn.io/The66Monkey/BASM-plus)
is reserved for future Postal-specific application-mail workflows. It is
documentation-only at present; it is not required for normal mailboxes or
ERPNext SMTP sending.
